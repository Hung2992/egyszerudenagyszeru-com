# PART I — THE SYSTEM CONSTITUTION

## 1. Non-negotiable principles

1. Preserve existing working functionality.
2. Inspect before modifying.
3. Maintain authoritative sources of truth.
4. Enforce all privileged permissions server-side.
5. Separate AI recommendations from actual authorization.
6. Bind approvals to exact action payloads and target versions.
7. Make consequential operations auditable.
8. Protect against duplicate and concurrent execution.
9. Verify actual outcomes independently.
10. Never represent simulated data as real business data.
11. Never represent forecasts as guaranteed outcomes.
12. Never fabricate integrations, metrics, execution results, or security status.
13. Require explicit approval for high-risk, financial, irreversible, and external actions.
14. Maintain an emergency stop mechanism.
15. Require documented tests before production releases.
16. Never allow an AI agent to modify its own security permissions.
17. Never sacrifice data integrity for automation speed.
18. Every autonomous capability must have an explicit scope and limit.

# PART V — EXECUTION AND TRUST ARCHITECTURE

## 28. Proof-carrying operations

Every consequential action must follow a governed lifecycle:

PROPOSED → VALIDATED → AUTHORIZED → APPROVED → QUEUED → EXECUTING → VERIFIED

Additional states:

REJECTED CANCELLED EXPIRED FAILED TIMED_OUT REQUIRES_REVIEW COMPENSATION_REQUIRED ROLLED_BACK

Approvals must be bound to the exact action, target, parameters, and version.

Revalidate authorization immediately before execution.

If the target has changed since approval, invalidate or re-evaluate the approval.

## 29. Deterministic execution boundaries

AI models must not directly control database privileges or bypass application policies.

Use:

- Registered tools
- Server-side policy enforcement
- Strict input schemas
- Explicit capabilities
- Transaction boundaries
- Idempotency keys
- Durable event delivery
- Execution receipts
- Independent verification

Never promise exactly-once execution when the underlying provider cannot guarantee it.

## 30. Emergency control

Create global and scoped shutdown mechanisms.

Allow authorized administrators to:

- Pause all autonomous execution.
- Pause individual agents.
- Pause specific workflows.
- Disable an integration.
- Disable model routing.
- Freeze high-risk actions.
- Enter read-only operational mode.

Emergency shutdown must be enforced by the backend.
